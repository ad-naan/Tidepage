# 光阴海岸：陪伴空间规划与模型规范

目标：用户带着自己的角色来到海边，自由探索、安静停留、遇见同行者，并带走一张共同的照片。视觉延续潮页的纸面、铅笔与海岸余晖，采用统一比例的绘本感 3D。

## 当前交付（人物、海湾、同行与纪念）

`/{locale}/explore` 默认进入落日海湾。指南中的「登上小船，探索群岛」保留原有航海玩法；航海中可以返回海湾。

- 程序化人物：独立头部、上臂、前臂、大腿、小腿关节；站立、行走、挥手和长椅坐姿。
- 装扮：4 种外套色、3 种肤色、3 种发色、3 种发型、挎包 / 围巾 / 无配件。使用固定资源与受校验的版本化配置；暂存当前设备，尚未绑定账号。
- 海湾资产：沙滩、草坡、连续木栈道、停泊小船、海边长椅、野餐手账、站长小屋、窗台花、信箱、远景灯塔及岛屿。
- 交互：点击地面寻路，WASD / 方向键行走，拖动环顾，滚轮与键盘调整镜头，辅助目的地导航。
- 拍照：渲染当前场景，预览并下载 PNG。照片不包含 HTML 工具与聊天，不上传服务器。
- 氛围：复用已有天空、反射海面、星空和海浪声；可切换昼夜。减少动态效果与后台暂停渲染。

已接入同一海湾的匿名多人连接、装扮和动作同步、三个独立座位、断线续接与独处切换。同行列表可找到真人站长（管理员角色且匹配指定账号）、步行靠近和邀请合照；双方确认后统一沙滩取景并倒数拍照。登录后可将真实地点打卡与合照元信息保存到账号的海岸手账。照片文件仍由本人下载，不提供云端相册。配置、数据库迁移、人数上限及 Redis 多实例状态见 [实时连接说明](realtime.md)。站长小屋是场景地点，不代表站长在线；离线向导尚未实现。

## 第一阶段建模约定

世界使用米为近似单位，Y 向上。角色默认面向 +Z，身高约 2.1 单位，脚底为局部原点；较大的头部与柔软轮廓便于远距离辨识。外套用海盐蓝、苔草绿、珊瑚粉、燕麦白；建筑以灰绿屋顶、暖白墙和木色呼应。

人物入口是 `runtime/createCoastAvatar.ts`，只接收 `domain/coast-avatar.ts` 的版本化配置。`root` 承载世界位置与朝向，`update(time, pose, reduced)` 驱动局部关节；材质切换不重建角色。模型拥有自己的资源释放方法。未来联网传输配置与动作，不序列化 Three.js 对象。

模型采用手工设定的曲线与顶点曲面塑形：脸颊、下巴和鼻尖是一张连续面，衣服采用轮廓放样，发束沿曲线扫掠；不是方块、球体的占位组合。角色关节当前为层级节点动画，尚未制作蒙皮骨骼、面部表情 morph 或自定义模型导入。

此前自建人物和海湾的离线模型未通过视觉验收，相关失败导出、重复渲染和生成脚本已经移出项目，不作为可用资产。当前运行时人物仍是待替换的旧模型。后续改用有明确授权的现成人物，核对实际外观、动作、尺寸和网页端成本后再接入；选型与授权记录集中保存在 [美术资源记录](art-direction/README.md)。

地标位置、可行走边界、房屋和长椅碰撞区域在 `domain/coast-harbor.ts`；场景资产在 `runtime/createHarborLandscape.ts`，控制器在 `runtime/createHarborScene.ts`，界面在 `ui/HarborView.tsx`。导航不能穿过小屋、长椅或走进海中。后续调整资产尺寸时须同步碰撞范围并验证路线。

## 空间建设顺序

| 阶段              | 内容                                             | 验收标准                                                               |
| ----------------- | ------------------------------------------------ | ---------------------------------------------------------------------- |
| 1：人物与海湾基础 | 当前单人模型、四个地点、装扮、动作、照片         | 可进入、行走、落座、换装、刷新恢复装扮、下载非空照片；原航海入口可往返 |
| 2：多人相遇       | 同房间身份与装扮、移动插值、动作、掉线重连       | 两个独立会话看见彼此；异常位置被拒绝；刷新或重连不留下重复角色         |
| 3：站长与纪念     | 站长亲自入场、离线向导、合影邀请、打卡与手账     | 真人 / 向导身份明确；参与者接受邀请后合影；纪念记录可跨设备读取        |
| 4：持续陪伴       | 专注营地、季节景观、星光海湾、共同点灯、小型活动 | 单人也有体验；低在线人数不影响探索；手机可降级运行                     |

第一版景观精修重点：落日水面光路、人物背影与长椅构图、夜间小屋暖灯、近景海岸细节。先对代表性桌面与移动设备实测帧率、首屏和内存，再确定模型细节及房间容量；8–12 人是起步验证目标，不是已有容量承诺。

## Socket.IO 已接入与后续扩展

沿用 `services/realtime` 独立网关、`shared/realtime/client.ts` 和已有 Redis Streams adapter。以 `docs/realtime.md` 为现有能力依据；旧后端路线图中「重新安装依赖 / 新建网关」等步骤已经过时，不重复搭建。

- 房间按海湾实例划分，例如 `coast:bay:<instanceId>`；邀请链接优先分配到同一实例，后续扩大地图才增加区域兴趣管理。
- 稳定参与者 ID 与 socket ID 分离。游客使用服务端发放的临时身份；登录复用 identity 会话，站长权限在服务端核验。作者桌面状态不能用来推断三维人物坐标。
- 客户端发送带序号的移动意图，服务端按碰撞、速度和权限计算状态。起步可验证 10–15Hz 快照广播，前端按时间戳插值，渲染循环独立运行。
- 公开数据仅含公开参与者标识、角色配置、位置、朝向和动作。暂停、镜头、音量和画质为个人偏好，世界时间与天气为房间共享状态。
- 位置和姿势为临时状态；角色装扮、合影会话、纪念印章与相册元信息需持久化。照片文件进入媒体存储，不通过 socket 广播大体积图片。
- 重连失败时重新拉取带 revision 的全量快照。对重要命令使用持久命令 ID、ACK 和幂等写入，不假设传输层保证业务恰好执行一次。

已注册 `world:join`、`world:input`、`world:appearance`、`world:identity`、`world:receipt`、`world:leave`、`world:snapshot`、`photo:invite` 和 `photo:respond`；动作作为输入中的明确枚举处理，拍摄会话通过仅双方可见的快照同步。当前发送 10Hz 全量快照，房间容量限制为 12；大型地图、自动分房、邀请链接、离线向导与云端装扮尚未实现。

多人合影采用独立会话：邀请 → 接受 → 锁定参与者和机位 → 服务端拍摄时刻 → 客户端渲染 → 本人确认保存。公开到社区相册单独征求同意。打卡由服务端依据真实位置和参与记录判定，按账号、纪念项和活动周期唯一写入。

## 体验与边界

- 先看风景再定制角色，保存到云端时才需要账号。安静状态、独处模式、拒绝邀请、屏蔽与举报随多人功能一起设计。
- 站长亲自进入才显示真人标识；离线时可增加明确标记的水獭向导，不将 NPC 包装成站长本人。
- 纪念围绕第一次抵达、点灯、遇见与季节风景，不设置断签惩罚。
- 弱设备提供较低像素比、减少阴影与反射成本；无 WebGL 时保留清楚的返回入口，后续提供静态看海模式。
- 所有界面文案进入已注册语言目录，控件复用 shared/ui；保持 `app → modules → shared` 的依赖方向。
