# 按模块开发后端与前后端联调

这份文档是全站后端开发的教学入口。按模块逐个完成，不以最近新增的友联页作为起点，也不一次性代做全部后端。每一轮先讲清需求、现有代码和待补边界，再一起实现、调试和验收。

## 现状与推进顺序

项目已有 Next.js 模块化单体、PostgreSQL / Drizzle、Redis 适配器、统一 HTTP 响应与错误处理。优先复用现有基础设施；有表或读取接口，不等于完整业务已完成。

| 顺序 | 模块 / 阶段          | 已有基础                                             | 要完成的闭环                                                                               |
| ---- | -------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 0    | 公共服务端基础       | 环境校验、迁移、缓存、健康检查、requestId            | 理解请求流向，启动本地服务并检查健康状态，区分 demo 与 postgres                            |
| 1    | 内容：文章读取       | 模型、表、双仓储、公开读取 API、列表详情与搜索       | 先联调文章列表、详情、筛选、分页、双语与 404，确认数据库变更反映到页面                     |
| 2    | 身份                 | users / sessions 表、会话读取、角色检查；UI 仍为预览 | 确定登录方式，再实现会话签发、过期、注销和站主权限，替换预览身份                           |
| 3    | 内容：管理与其他内容 | 手记、项目、一言已有读取；尚无编辑发布接口           | 用真实站主身份完成文章草稿、编辑、发布、下架与缓存失效；再逐项联调手记、项目、一言         |
| 4    | 媒体与照片廊         | 播放器、照片廊和本地导入预览                         | 明确需持久化的资源，接上传、元信息、访问地址与删除权限，再联调照片列表与预览；音乐按需接入 |
| 5    | 互动                 | 评论、回应、点赞等前端演示                           | 接真实身份和存储，联调回复、分页、权限、重复提交与失败重试，一项项替换本地状态             |
| 6    | 友联                 | 领域协议、示意数据入口、页面                         | 做公开列表和站主管理，再做申请审核，复用身份、权限与请求能力                               |
| 7    | 世界                 | 航程规则、Three.js、本地体验、PubSub                 | 先账号存档，再评估在线状态、独立实时网关和多人同步，保持领域与渲染分离                     |

首页聚合与站点外壳随数据源一起联调；自述等静态文案继续留在语言包。访客统计等扩展单独确认需求，不把装饰性数据默认变成后端任务。

## 每个模块怎么一起做

1. **需求与验收**：列出这轮用户操作、当前演示行为和完成标准。
2. **走读现有代码**：指出路由、领域、用例、仓储、服务端入口、UI 的位置，解释已有部分如何复用。
3. **数据与接口**：先讲字段、关联、状态、权限与错误，对照页面确定请求和响应，再写代码。
4. **实现一小段**：按 domain → application → infrastructure → server → route 推进；改表时一起看迁移 SQL。
5. **联调真实链路**：先验证接口，再接页面；查看响应与 requestId，覆盖适用的加载、空数据、失败、权限状态。
6. **验收再继续**：说明改动、测试、你需要掌握的概念和下一小步。每次只推进一个可解释、可验证的功能，留出你操作和提问的机会。

Server Component 通过模块 server 入口读取数据，不向自身 HTTP API 绕一圈；浏览器使用 shared/http/client。写入必须服务端校验和授权。UI 继续复用 shared primitives，遵守 `app → widgets → modules → shared`。

## 第一轮从这里开始

先做“公共基础 + 内容模块的文章读取”，不先做友联申请。

- 走读 `src/app/api/v1/articles/route.ts` → `src/modules/content/server/index.ts` → application/service → repository → PostgreSQL adapter，并对照文章列表页面理解服务端直读。
- 检查本地 Node、数据库连接和 CONTENT_SOURCE，解释变量作用；不输出连接密码、不覆盖已有环境文件。
- 启动本地 PostgreSQL，执行已有迁移和开发种子；切换 postgres 并重启，调用 health/ready 与文章列表接口。
- 用开发文章串起列表、详情、搜索、翻译和未发布过滤，确认数据库与页面一致。
- 运行 `npm run check`、`npm run build` 并记录真实服务联调结果；PGlite 测试不能替代 PostgreSQL 连接验证。
