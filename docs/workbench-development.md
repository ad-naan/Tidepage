# 工作台实现与后续边界

入口为 `/zh-CN/admin` 和 `/en/admin`。GitHub 或 Gitee OAuth 会话与前台共用。保存会更新 PostgreSQL 工作副本，文章和手记的发布操作另行写入公开内容。

## 已实现

- 桌面固定外壳，导航与内容分别滚动；手机自然页面滚动。后台跳过前台整页过场，动态内容路由按栏目挂载，避免旧列表闪到新栏目。读屏提示区固定定位，避免在文档末尾多撑一像素。
- 文章支持服务器草稿、版本冲突检查、回收站和逐语言发布。打开属性中的「发布前检查」，保存后发布当前语言。发布日期采用站点时区，留空时首次发布立即生效。发布需要迁移 `0009`。
- 手记、项目、一言的后台列表直接读取正式记录和工作副本。编辑旧记录时沿用原 ID，保留结构化正文，保存工作副本后按语言发布。照片廊和友联可按语言发布或下架，仅限站主。评论尚无后台管理页。
- 站点设置：站主保存的站名、默认 SEO 标题、站点简介和 SEO 简介按语言用于网页标题、分享元信息、JSON-LD、RSS 和 llms.txt。首页文案、作者资料及社交链接、头像和分享图由对应视图读取；留空时使用站点默认值。精选文章按 slug 排序并用近期文章补足，导航在原有分组内排序；页脚和公开联系说明读取保存配置。原联系备注保持私密，不自动公开。
- 共享文件选择、日期时间日历；Dialog 标题固定，内容内部滚动，滚动条在纸面内侧；Select Portal 在 dialog 内保持正确层级。
- 设置表单回填当前语言的默认姓名、首页介绍、社交链接、站名、导航和联系说明；可选首页 / SEO 覆盖项用当前基础资料作输入提示，并注明优先关系。头像选择器展示默认作者图片，字段旁说明展示位置。登录账号资料单独展示，避免与站点作者资料混淆。

## 字段与国际化

界面语言来自注册 catalogs；内容语言独立选择。同一 id 下各语言分开保存，缺少英文时不以中文正文回填。

| 项目     | id、revision、排序、分类、插画、色调、内容日期、更新时间、回收站状态                                                       | 名称、副标题、介绍、展示状态、技术栈输入                             |

| 友联     | id、revision、url、category、sortOrder、deletedAt                                                                          | 站名、介绍                                                           |

工作副本 DTO 在所属业务模块的 domain 定义，界面与服务器共用校验。平台的 `workbench_records` 按站主和记录组隔离保存工作状态；更新使用服务器 revision 条件写入，跨设备的过期写入返回冲突。工作副本与前台 draft / published 分开，正式发布流程仍需校验技术栈数组、导航可选值、自述分节和发布修订。

## 富文本

`content/domain/editor-document.ts` 定义版本化草稿与支持的节点 / marks；正文以 ProseMirror JSON 为事实来源，不同时维护 Markdown / HTML 正文。`legacy-draft.ts` 导入前台分节结构，测试覆盖电影原片名、导演、年份、封面与说明，网页站名与图片，以及提示块和代码说明的保留。

数据库文章、手记和项目支持可选的结构化 `body`（JSONB）。阅读页与 Markdown 输出优先读取它；没有 `body` 的现有文章继续使用原分节正文。建立文章工作副本时直接保留结构化正文。迁移图片使用内容寻址的本地文件，可在编辑器中预览、替换和裁剪。旧 MySQL 数据的转换、备份和导入流程见 [迁移说明](legacy-mysql-migration.md)。

Tiptap 实例独立于外层表单，不在每个输入事务把整篇 JSON 写进 React state。各语言保留自己的实例、选区和撤销历史，预览不销毁编辑实例；只在保存和显式快照时序列化。依赖依据：[Tiptap 性能指南](https://tiptap.dev/docs/guides/performance)。

已接入基础格式、标题、列表、待办、引用、代码、表格、图片与来源卡片，支持 Markdown 输入快捷方式和选区浮动工具。`/` 菜单靠近光标定位，不挤动正文。图片可调整宽度、拖动尺寸、对齐、填写说明、替换、裁剪与恢复原图。

编辑画布最大宽度 1040px；正文默认滚动高度为视口的 48%，限制在 280–520px，可展开至视口的 72%（最多 820px）。专注模式隐藏工作台导航，Escape 退出；浏览器支持时提供原生全屏，正文阅读列最大 800px，工具栏保持在滚动正文外。Select、浮层和反馈支持全屏层级。标题和正文为主区，属性（包括摘要、SEO、封面与发布设置）和 AI 从页头按需展开。常用格式留在工具栏，插入菜单与斜杠菜单复用内容块定义，支持中英文关键词筛选、方向键和回车；Escape 收起菜单并恢复入口焦点。图片操作浮在图片内侧，选中后显示，尺寸 / 对齐 / 替代文字 / 说明集中到图片设置弹窗。

后台路由与本地数据初始化复用 `shared/ui/loading/LoadingSkeleton`；骨架在 180 ms 后显现，500 ms 后显示加载说明。后台切页用顶部细进度条，工作区短暂淡入；按钮提供等待状态，弹窗支持进入与退出过渡。降低动态效果时取消循环动画和位移。导航预取完整后台路由（Next 仅在生产启用预取），共享页头、侧栏和工作区滚动容器保持挂载。

音乐目前为来源卡片，不加载第三方播放器；电影与网页资料手动录入，不自动抓取。部分历史元数据能保存但尚无高级编辑控件。多人协作、评论锚点、完整版本历史、离线自动恢复日志、公式、图表、多列及全部块拖拽尚未实现，不能宣称达到成熟文档产品的完整体验。

## 资源与上传

`media/domain/assets.ts` 定义 ImageUploader，编辑器、媒体库和裁剪共用 `media-client.ts`。文件通过同源 `/api/v1/media` 上传，服务器检查实际图像格式、尺寸和大小，然后按 SHA-256 命名存入 `UPLOAD_DIR`。允许 JPEG / PNG / WebP / GIF，单张最多 12 MB，每边最多 20000 像素，总解码像素上限 4000 万。SVG 和伪装的 HTML 不接受上传。

默认目录为 `storage/uploads`，可在根目录 `.env` 中通过 `UPLOAD_DIR` 修改。访问地址统一为 `/uploads/<hash>.<ext>`；正文中的 assetId 就是稳定的资源路径。媒体元信息保存在 PostgreSQL 的 `media_assets`，列表和归档按站主隔离；归档不删除文件，引用仍可显示。图片通过校验过的文件名读取，响应带实际 MIME、nosniff 和不可变缓存头。上传、列表及工作副本接口要求 author/admin 会话；变更接口同时校验来源，限制请求体大小。

应用 `0013_gallery_photo_capture.sql` 后，新上传的照片会提取相机、镜头、焦距、光圈、快门和 ISO。含 EXIF、IPTC、XMP 等元数据的文件在写入公开媒体存储前会清理这些元数据，静态图像会应用 EXIF 方向。上传有 GPS 的原图时，服务器在本地查找 25 公里内最近的城市，只保存城市名。编辑时可修改或清空地点。发布照片时同步保存可展示的拍摄参数和所选地点。已有图片文件不会被改写，要给旧照片补充拍摄参数，可以重新上传原图并替换后发布。

`photo-cities.tsv.gz` 由 [GeoNames cities15000](https://download.geonames.org/export/dump/) 数据筛选并压缩而成，包含用于匹配的城市中心坐标及英文、可用的中文名称，按 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) 许可分发。

裁剪使用 [React Easy Crop](https://github.com/ValentinH/react-easy-crop)，生成新 PNG，不覆盖原 Blob。正文保存 originalAssetId，可恢复原图，撤销也保留旧引用。最长输出边 4096 像素，GIF 裁剪为静态图，界面有说明。媒体回收站只取消可选状态，不删除被引用的 Blob。

部署时挂载持久化资源目录并备份它；不要将图片写入构建输出。后续对象存储适配器可以复用 ImageUploader 和资源模型，签名 URL 等能力按部署需要增加。

## 站主配置

在根目录 `.env` 配置 GitHub/Gitee OAuth 应用的 client ID 与 secret（见 `.env.example`），回调为 `<SITE_URL>/api/v1/auth/github/callback` 或 `/gitee/callback`。运行 `pnpm admin:setup --github <用户名> --gitee <用户名>`，将平台固定数字 ID 绑定到同一个站主账号；已有站主记录、内容归属和展示名保留。只使用一种平台时只传对应参数。多名管理员时用 `--user-id <uuid>` 明确选择；身份已属于其他账号时命令会拒绝，不自动合并数据。已核实数字 ID 时可使用 `--github-id <id>` / `--gitee-id <id>` 离线绑定。后续前台与后台统一第三方登录；普通访客首次登录只创建 reader，无后台权限。旧访问密钥登录接口与管理员环境变量已移除。会话 cookie 为 HttpOnly，生产 HTTPS 使用 Secure；数据库只存会话令牌的哈希，默认有效期 12 小时。后台可退出登录。

`shared/lib/workbench-store.ts` 封装工作副本的读取和条件更新，确保内容与预期版本来自同一次读取；业务组件不自行实现数据库或存储适配器。旧浏览器工作区不会被读取或清除。

OAuth 登录同步的公开头像保存在 `identities.profile_avatar_url`，无需新增重复字段。会话和评论读取最近更新的非空头像，双平台绑定不重复评论行；现有会话刷新后即可读取已保存的头像。登录入口、账号面板和评论共用带加载失败回退的 Avatar。世界同行者头像通过服务端签名身份票据进入房间快照，身份过期或退出后清除，不能由客户端冒充。更新后需重启独立 realtime 服务才能使用新的头像消息字段。站点左上角作者图片继续由站点设置管理。

## 写作与站点助手

`ai/domain/writing.ts` 定义输入、delta / done 事件。HTTP 适配器只接受同源端点；SSE 解析器支持 UTF-8 跨块、CRLF、多行 data 和 AbortSignal，缺少 done 视为中断。provider 密钥不进浏览器。

在根目录 `.env` 中配置 `AI_CHAT_COMPLETIONS_URL` 和 `AI_MODEL`。需要认证的模型服务同时配置 `AI_API_KEY`。地址填写完整的 Chat Completions URL。配置后重启 Web。

- 文章助手支持流式润色、生成标题、摘要、标签和 SEO 字段，以及按语言翻译。全文翻译保留块结构、链接、媒体引用和代码。较长文章可以选中一段处理。
- 编辑器的「发布前检查」使用支持 Chat Completions 工具调用的模型。Article Review Skill 注册读取已保存草稿、搜索公开文章、检查 SEO 和预览 RSS 四个只读工具。运行时维护本次检查的消息和证据，限制工具调用、上下文和请求时间。每条建议引用工具证据，保存或发布仍由作者操作。
- `src/modules/ai/server` 包含工具循环、模型传输与 MCP 适配器。`src/modules/content/server/publication-review.ts` 定义文章检查 Skill，业务工具与报告约束在此组合。可在根目录 `.env` 配置 `AI_MCP_PUBLICATION_URL`、`AI_MCP_PUBLICATION_TOOL` 和可选的 `AI_MCP_PUBLICATION_TOKEN`。适配器支持 Streamable HTTP 上声明 `readOnlyHint` 的文本工具，当前只传内容语言。
- 站点设置的基础信息区可以生成 SEO 标题、描述与 GEO、RSS 检查建议。RSS 和 `llms.txt` 根据公开内容生成，站主可以直接预览产物。
- 主动生成时才将相关文字发送给模型。采纳后的内容进入草稿，随后可以保存和发布。生成期间草稿发生变化时，需要重新生成。
- 编辑器工具栏可查看大纲或操作当前块。`Alt/Option + Shift + ↑/↓` 可移动当前块，撤销使用编辑器历史。

同一模型可用于海湾水獭。设置 `AI_GUIDE_ENABLED=true` 后，登录读者可走到水獭身旁提问。回复显示在跟随角色的场景气泡中，底部只保留简短输入栏；它参考公开站点栏目、近期文章和当前地标，点击推荐目标才会移动角色。真实模型、场景对话与写作流式接口的验收记录见 [场景实测](world-playtest.md)。

AI 接口共用服务端模型出口。部署前先执行 `pnpm db:migrate` 应用 `0012_ai_usage_budget.sql`。水獭问答和动物聊天合计每账号每分钟 10 次、每 UTC 日 24 次模型调用。可信反代提供客户端地址时，同一地址合计每分钟 30 次。编辑后台按账号每 UTC 日最多 300 次模型调用，翻译的每个批次和发布检查的每轮模型请求分别计入。

全站每天有两份独立的使用预算，读者由 `AI_HARBOR_DAILY_UNITS` 控制，默认 100 万，编辑后台由 `AI_EDITORIAL_DAILY_UNITS` 控制，默认 800 万。单位按发往模型的请求字节数加预留的最大输出 token 数计算，供应用侧限额使用。额度在发请求前通过 PostgreSQL 原子扣减，跨 Web 实例共享。额度用尽返回 429，预算数据库不可用返回 503。已预留的额度不会因客户端断开或模型返回错误而返还。

## 验证与推进

运行 `pnpm run check`、`pnpm run build`；浏览器验证双语独立正文、跨语言撤销、刷新恢复、冲突、图片插入 / 裁剪 / 对齐、流式停止、未保存离开、回收站恢复、Dialog 长短内容、日历键盘及桌面 / 手机。

`pnpm run db:check` 核对 PostgreSQL 连接和迁移；`pnpm run db:verify` 在单个未提交事务中使用临时记录检查设置、草稿、发布、回收站和多语言隔离，最后回滚并确认没有保留测试记录。它不代替浏览器交互验证，也不验证上传文件或外部 OAuth / AI 服务。Redis 需要与服务器一致的认证配置；缓存降级到数据库不能作为 Redis 已联通的证据。

后台变更接口在服务端检查会话角色和请求来源。
