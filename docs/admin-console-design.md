# 潮页工作台：站主管理后台设计

状态：设计基线。首轮后台前端已开始实现，实际能力与未接入的服务以 [工作台开发说明](workbench-development.md) 为准。仍不实施生产数据库、鉴权或管理 API。

## 产品定位与设计

前台像一本留在海边的手账，工作台是这本手账的整理桌。沿用纸色、墨色、暖橙、宋体标题和铅笔选中笔迹；操作区用清晰的 UI 字体与紧凑列表。小插画只在空态和欢迎区出现，不加入世界场景、音乐播放器、访客动画或大面积卡片统计。

桌面采用左侧分组导航、上方当前位置与预览入口、中央工作区。正文编辑为主列加发布设置侧栏。小屏导航折叠，表单上下排列，主要操作不依赖悬停；手机支持查看与简单编辑，不挤压完整编辑器。继续支持深色、减少动效、键盘操作和中英文目录文案。

## 核心页面

### 工作台

欢迎语旁只有“写文章”主操作。下方按优先级显示草稿、待处理来信和最近修改；每条都能跳到具体编辑页。所有数量来自同一数据源；前端设计期标记示例数据，不制造访问量与增长趋势。

### 文章列表与编辑

列表列为标题 / 分类 / 语言 / 发布状态 / 最近修改 / 操作；支持标题搜索及全部、草稿、已发布筛选。行操作保留“编辑”，其他操作收进操作菜单；首版不默认加入批量删除。

编辑器上方为面包屑、保存状态、预览、保存草稿与发布。主列放标题、摘要、分节正文；侧栏放分类、标签、语言、slug、发布日期、阅读时间与插画。复用已有内容 schema 和段落 / 代码 / 链接等块协议，不同时维护一份 Markdown 正文和一份结构化正文作为双重事实。

首次实现先支持现有内容结构，再逐步改善编辑体验；块编辑器留在 content 业务域，只有确实无业务含义的工具栏基础件才进入 shared。

工作流：新建 → 编辑草稿 → 显式保存 → 按前台排版预览 → 检查发布设置 → 发布 → 前台查看；已发布内容先保存工作副本，点击“更新发布”才改变公开版本。这个工作副本 / 公开版本分离是待设计的后端能力，现有表尚未支持，不能假装普通保存就已有版本隔离。

首版用显式保存，显示未保存标记，离开时提示。后续接自动保存需要冲突检测与失败恢复。预览未发布内容使用受授权的专门入口，不能放开公开文章 API 的过滤规则。未来持久化状态先对应现有 draft / published，不先扩展一套无人使用的状态系统。

### 站点设置

| 页签       | 可编辑内容                           | 边界                                                 |
| ---------- | ------------------------------------ | ---------------------------------------------------- |
| 基本信息   | 中英文站点名、介绍、默认分享信息     | 校验长度与必填；发布前展示差异                       |
| 个人资料   | 姓名、头像、身份、首页介绍与公开外链 | 外链校验；头像选择媒体资源                           |
| 首页与导航 | 首页内容选择、已实现栏目的显示和顺序 | 不让“添加导航”生成不存在的页面，不允许注入 JSX / CSS |
| 自述       | 分节标题、正文、签名                 | 业务内容与界面文案分离                               |
| 页脚与分享 | 页脚说明、公开联系方式、默认分享图   | 移除示例联系方式后才发布                             |

设置分为工作副本、预览和应用到网站，保存前显示错误，应用前可比较变更。可编辑的站点业务内容未来从配置服务读取；按钮标签、系统错误等 UI 文案仍放 locale catalogs。设计 token、任意翻译 JSON、数据库地址、Cookie 密钥、OAuth 密钥、部署域名和基础设施开关不作为普通设置表单字段。

SITE_URL 继续由受控部署配置提供，后台只展示脱敏的连接或运行状态，不通过内容编辑改变 canonical 来源。主题只提供已实现的选项，不提供任意 CSS 输入框。

### 媒体、友联和互动

媒体库显示缩略图、文件名、类型、大小、引用数与上传状态；编辑器从媒体库选择已有资源。上传按钮的本地预览和未来真正入库的成功状态必须区分。删除前先查引用，必要时先替换关联内容。

友联“已展示站点”和“申请队列”分开；申请里的私有联系信息只在审核详情可见，不流入公开 DTO。互动列表按处理状态筛选，能回到所属文章 / 手记。回复、隐藏、通过审核等动作成功后才更新状态，失败提供重试。

## 通用交互约定

- 页面同时设计正常、加载、空态、请求失败、未授权、会话过期和未保存状态；提交期间禁用重复操作，保留可恢复输入。
- 提示复用 NoticeProvider；成功文字区分“草稿已保存”“文章已发布”和“站点设置已应用”。前端示例操作必须标注预览，不显示真实入库承诺。
- 长表单使用页面，短编辑使用 Dialog；确认框只用于发布覆盖、撤回和删除等需要明确后果的动作，不把每次保存都弹窗。
- 删除显示对象名、关联影响与恢复方式；首版优先撤回和保留草稿。永久删除等后续操作单独设计。
- 编辑冲突不得静默覆盖，后端接入时使用版本或 updatedAt 并提供重新加载 / 保留副本。
- 后台不进入公开导航、RSS 或 sitemap，设置 noindex；真实权限在服务端每次读写校验，不能依赖隐藏入口或演示登录。
- 首版面向一个站主，使用已有 admin 角色；author 的内容编辑范围若要开放，另行确定。管理私人数据和站点设置不能默认授权给所有登录用户。

## 目录与复用

后续前端落地建议：

```text
src/app/[locale]/(admin)/admin/   路由、权限入口、SEO 与组合
src/widgets/admin-shell/        工作台侧栏、顶部工具、窄屏导航、Notice 组合
src/modules/dashboard/ui/       工作台待办与最近修改聚合
src/modules/content/ui/admin/   文章 / 手记 / 项目 / 一言列表与编辑
src/modules/media/ui/admin/     媒体库与上传、资源选择业务视图
src/modules/engagement/ui/admin/评论审核与回复
src/modules/friends/ui/admin/   友站编辑与申请审核
src/modules/identity/ui/admin/  管理登录与账号视图
src/modules/site-settings/      可编辑站点业务配置；初期只有 domain / ui
src/shared/ui/                  复用已有按钮、字段、选择器、弹窗、反馈、文字与手绘材料
```

gallery 当前在 content/ui，后续管理界面先放 content/ui/admin/gallery；资源上传依赖 media 的公开接口，不直接访问它的 infrastructure。dashboard 只聚合已暴露的模块 DTO，不复制各模块数据模型。

不要建立万能 `modules/admin` 来包揽所有业务，也不把业务表单扔进 shared。若列表确实需要统一表格，先在 shared/ui/table 建立基础语义与键盘约定再复用；表头、列定义、筛选和行操作留在业务模块。复用样式 token 与 primitives，前台和后台分别有自己的 shell，后台不 import 前台 widget。所有最终 UI 文案进入注册语言包。

## 现在的落地顺序

1. 先评审工作台设计预览与上述管理范围。
2. 只做后台前端：AdminShell → 总览 → 文章列表与编辑 / 预览 → 站点设置 → 其余管理列表。使用清晰标注的演示 DTO，不开放管理写 API，不新增迁移。
3. 完成桌面 / 小屏 / 深色 / 键盘、离开未保存内容与长表单交互验收。
4. 前后台操作模型清楚后，再按模块一起开发：公共基础与身份授权 → 内容完整读写 → 媒体 → 站点配置 → 互动 → 友联 → 世界。每个模块同时验收后台操作和前台结果。

第一条正式联调应能覆盖“站主登录 → 后台保存草稿 → 预览 → 发布 → 前台读取”，不要把只有公开列表读取当成网站管理功能已经完成。
